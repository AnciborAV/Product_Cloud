# Зелёная лавка

Магазин на Java 25 и Spring Boot 4.1.2: каталог, личный кабинет, выбранные товары и публичные отзывы. Серверные страницы на Spring MVC и Thymeleaf, PostgreSQL, Spring Data JPA, Spring Security и миграции Flyway.

## Возможности

- Регистрация, вход по логину и паролю, выход. Логины нечувствительны к регистру, пароль хранится как BCrypt-хеш.
- Личный кабинет с фотографией, выбранными товарами и собственными отзывами.
- Загрузка JPEG/PNG до 2 МБ: проверка содержимого и разрешения, обрезка и перекодирование в JPEG 400×400. В PostgreSQL хранится только итоговый аватар, оригинал не сохраняется.
- Добавление и удаление выбранных товаров. Повторное добавление не создаёт дубликат, включая параллельные запросы.
- Отзывы с оценкой 1–5, редактированием и удалением. Один отзыв пользователя на товар; обновление заменяет прежний текст. Отзывы сразу публикуются во вкладке «Отзывы покупателей» с именем автора.
- Каталог с поиском по русским названиям, категориями и страницами по 12 товаров. Публичные отзывы также имеют постраничный вывод.
- Добавление товаров на витрину доступно только роли `ADMIN`. Регистрация всегда создаёт покупателя `USER`.
- Адаптивные страницы, доступные подписи форм, состояния пустых списков, уведомления и страницы ошибок.

## Запуск

Нужны JDK 25 и PostgreSQL 17 (либо Docker Compose). Maven запускается через Wrapper.

1. Скопируйте `.env.example` в `.env`, задайте собственный `DB_PASSWORD`.
2. Запустите PostgreSQL:

```sh
docker compose up -d postgres
```

3. Передайте переменные в процесс приложения. Compose читает `.env` сам, Spring Boot — нет. Для файла с указанным в примере форматом:

```sh
set -a
source .env
set +a
./mvnw spring-boot:run
```

Откройте http://localhost:8080. Создайте аккаунт по ссылке «Личный кабинет» → «Создать аккаунт».
Flyway автоматически создаст таблицы и начальный ассортимент. Повторный запуск не сбрасывает данные; Compose сохраняет их в именованном томе. Пароли аккаунтов и учётные данные базы не включены в репозиторий.

При использовании существующей PostgreSQL укажите `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`. Создайте отдельную базу для приложения и предоставьте пользователю права на её схему. Приложение проверяет соответствие JPA схеме (`ddl-auto=validate`); схему изменяет только Flyway.

## Администратор

Зарегистрируйте отдельный аккаунт, затем через доверенное подключение к базе назначьте ему роль:

```sql
UPDATE user_accounts SET role = 'ADMIN', version = version + 1,
 updated_at = CURRENT_TIMESTAMP WHERE username = 'your_admin_login';
```

После назначения роли войдите заново: форма добавления товаров появится внизу каталога. Общего административного пароля и публичного API назначения ролей нет.

## Проверка

```sh
./mvnw clean verify
```

Обычный запуск тестов использует H2 в режиме PostgreSQL, применяя те же миграции Flyway. Для проверки на настоящей PostgreSQL создайте **отдельную пустую тестовую базу**, передайте её настройки:

```sh
./mvnw test \
  -Dspring.datasource.url=jdbc:postgresql://localhost:5432/fresh_market_test \
  -Dspring.datasource.username=fresh_market \
  -Dspring.datasource.password="$DB_PASSWORD"
```

Тесты создают записи в указанной базе: не используйте рабочую базу магазина. Проверяются миграции, поиск и точность цены, рендеринг страниц, валидация, регистрация и вход, права администратора, CSRF, изоляция пользователей, конкурентное сохранение товаров, публикация и экранирование отзывов, редактирование и загрузка настоящего изображения.

## Архитектура

- `model/BaseEntity`: UUID, время создания/изменения, optimistic locking через `@Version`.
- `ProductEntity`, `UserAccount`, `SelectedProduct`, `Review`: сущности PostgreSQL; `Product` — неизменяемая модель представления товара.
- `repository`: JPA-запросы, загрузка связей через EntityGraph, блокировка строки пользователя для последовательного изменения его подборки и отзывов.
- `service`: транзакции и бизнес-правила; `AvatarProcessor` отдельно проверяет и преобразует изображения.
- `dto`: формы с Jakarta Validation; `controller`: маршруты, ошибки форм и Post/Redirect/Get.
- `db/migration`: версия схемы, внешние ключи, уникальность пар пользователя/товар, ограничения оценок и индексы.

Open Session in View отключён. Доступ к изменяемым данным определяется текущим пользователем из сессии, а не переданным в форме идентификатором владельца. Формы защищены CSRF; HTML от пользователей экранируется Thymeleaf. У сессии тайм-аут 30 минут, cookie HttpOnly/SameSite=Lax, страницы получают Content Security Policy и стандартные защитные заголовки Spring Security.

## Развёртывание

Сборка: `./mvnw clean package`, запуск: `java -jar target/Spring_DEMO-0.0.1-SNAPSHOT.jar` с переменными базы в окружении. При HTTPS задайте `SESSION_COOKIE_SECURE=true`. TLS, ограничение частоты входа/регистрации на reverse proxy, резервное копирование PostgreSQL и мониторинг необходимо настроить в среде размещения. Оплата и восстановление пароля по почте в текущий объём функций не входят.


## Контакты и письма со списком продуктов

При регистрации укажите имя, фамилию, телефон и email. Для ранее созданного аккаунта
заполните эти поля в личном кабинете. Вход выполняется по логину и паролю.
В `user_accounts` имя хранится в `display_name`, остальные контакты — в `last_name`,
`phone`, `email`. В `selected_products.product_name` хранится название товара на момент
добавления; миграция V4 заполнит названия ранее сохранённых товаров.

После каждого фактического добавления или удаления товара полная подборка помещается
в `selection_mail_outbox` в той же транзакции. Удаление последнего товара создаёт письмо
«Список пуст». Повторное добавление уже выбранного товара не создаёт письмо.
Обновление контактов также отправляет текущий список на новый адрес.

Для отправки задайте переменные окружения (секреты не включайте в репозиторий):

```properties
MAIL_ENABLED=true
MAIL_FROM=your-address@example.com
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=your-address@example.com
SMTP_PASSWORD=your-mail-app-password
SMTP_AUTH=true
SMTP_STARTTLS=true
SMTP_SSL=false
```

Для SMTP с неявным TLS на порту 465 задайте `SMTP_PORT=465`, `SMTP_SSL=true`,
`SMTP_STARTTLS=false`. Используйте настройки своего провайдера. Без `MAIL_ENABLED=true`
письма остаются в очереди и будут отправлены после настройки SMTP. Обработчик проверяет
очередь каждые 30 секунд, сбои отправки повторяются. `sent_at` отмечает принятие письма
SMTP-сервером, `attempts` — число попыток. При аварии после SMTP-отправки, но до фиксации
транзакции возможна повторная доставка. Email не проходит подтверждение владения:
перед включением отправки проверьте указанный адрес.

Просмотр своей подборки в базе:

```sql
SELECT sp.product_name, sp.created_at
FROM selected_products sp
JOIN user_accounts u ON u.id = sp.user_id
WHERE u.username = 'your_login'
ORDER BY sp.created_at DESC;
```


## Каталог и отправка заказа

Миграция V5 расширяет начальный каталог до 50 продуктов в 10 категориях, сохраняя
идентификаторы и связи существующих товаров. Фрукты и овощи разделены. Фотографии
хранятся локально в `static/images/products`; соответствие названиям задано явно,
источники перечислены в `sources.json`. Это демонстрационные фотографии продуктов,
а не фотографии конкретной упаковки производителя; цены также демонстрационные.
Структура отделов ориентируется на https://av.ru/catalog.

В личном кабинете кнопка «Отправить заказ на электронную почту» добавляет текущую
подборку в очередь. Письмо содержит по одной упаковке каждого товара и итоговую сумму.
Получатель — email из контактов текущего пользователя: для вашего аккаунта сохраните
`AnciborAV@mil.ru`. Адрес не подставляется в аккаунты других покупателей.

Если `MAIL_ENABLED=false`, кнопка показывает понятную ошибку и не создаёт новую заявку.
Для реальной доставки нужны `MAIL_ENABLED=true`, `MAIL_FROM` и действительные параметры
SMTP из раздела выше. Адрес получателя сам по себе не задаёт исходящий SMTP-сервер.
Приложение не читает `.env` автоматически: передайте переменные при запуске и перезапустите
процесс. Сообщение «поставлен в очередь» не означает доставку в почтовый ящик.
Проверьте `sent_at`, `attempts` и журналы при проблемах; после приёма SMTP-сервером
проверьте также спам и ограничения принимающего почтового сервера.


## Локальная отправка через iCloud

При запуске из корня проекта приложение автоматически читает `.env.smtp.properties`
(при запуске JAR файл должен находиться в текущем рабочем каталоге). Файл исключён
из Git правилом `.env.*` и не входит в JAR. Переменные окружения имеют приоритет.

Для iCloud используются `smtp.mail.me.com:587`, STARTTLS и полный адрес отправителя
в `MAIL_FROM` и `SMTP_USERNAME`. В `SMTP_PASSWORD` нужен пароль приложения Apple,
созданный в https://account.apple.com/ → «Вход в учётную запись и безопасность» →
«Пароли приложений». После сохранения настроек и включения `MAIL_ENABLED=true`
перезапустите приложение. При включении отправляются и ранее накопленные письма.


## Фирменные письма и смена пароля

Письма содержат HTML-оформление в цветах «Зелёной лавки», имя отправителя,
подпись команды и альтернативную текстовую версию. HTML самодостаточен:
внешние изображения, шрифты и CSS не нужны; пользовательский текст экранируется.
Все ранее поставленные в очередь письма также получают новое оформление.

В личном кабинете раздел «Сменить пароль» запрашивает текущий пароль, новый пароль
(от 10 символов, максимум 72 байта UTF-8) и его повтор. Восьмизначный код приходит
на email аккаунта и действует 15 минут с момента запроса. До ввода кода старый
пароль остаётся действующим. Повторный запрос разрешён через минуту и отменяет
предыдущий код; после пяти неверных попыток требуется запросить новый.

Код привязан к пользователю и email на момент запроса: после изменения email
требуется новый запрос. В `password_changes` хранятся SHA-256 кода и BCrypt нового
пароля; сам пароль не попадает в письмо или очередь. Письмо с кодом временно
содержит код в существующей почтовой очереди: доступ к ней должен быть ограничен.
Истёкшие или заменённые письма с кодами не отправляются. Письма с действующими
кодами имеют приоритет перед заказами. После подтверждения запрос удаляется,
все зарегистрированные сеансы пользователя завершаются, а на email поступает
уведомление о смене. Следующий вход возможен с новым паролем.

Миграция V6 добавляет таблицу запросов и поля типа, темы и срока действия писем.
Тесты отключают настоящую доставку независимо от локальных SMTP-настроек.
