# Product Cloud

Учебный продуктовый магазин: Java 25 LTS, Spring Boot 4.1.1, Spring MVC,
Thymeleaf, JPA и Maven. Содержит каталог, регистрацию, профиль, личную корзину и историю заказов.

## Быстрый запуск без PostgreSQL

```sh
./mvnw clean verify
./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
```

Откройте http://localhost:8080/products. Профиль demo сохраняет H2 в `data/`.
В Windows замените `./mvnw` на `mvnw.cmd`. Нужен JDK 25.

## PostgreSQL

Создайте базу products. Укажите DB_PASSWORD; DB_USERNAME по умолчанию postgres,
DB_URL — jdbc:postgresql://localhost:5432/products.

```sh
export DB_PASSWORD='your-local-password'
./mvnw spring-boot:run
```

Приложение слушает только localhost. SERVER_ADDRESS позволяет явно изменить адрес.
Сессионная авторизация защищает личные страницы и изменяющие операции.
Для публичного размещения дополнительно настройте HTTPS, Secure-cookie, резервное
копирование, миграции, ограничения частоты входа и почтовые сценарии.

## Изменения

- BigDecimal и numeric(19,2) вместо double: цены не теряют десятичную точность.
- Проверки названия, диапазона и точности цены на форме и в модели.
- Constructor injection, транзакции сервиса и неизменяемые ProductView.
- Обновление/удаление отсутствующего товара дают ProductNotFoundException.
- Post/Redirect/Get предотвращает повторную отправку формы при обновлении страницы.
- Пагинация по 20 товаров, стабильная сортировка, адаптивная страница и ошибки рядом с полями.
- Удалены Lombok, MySQL-драйвер и IDE-файлы. Используется один понятный стек.

## Данные и проверка

Сохранены таблица products, Integer id и последовательность products_seq (шаг 50).
Для учебной разработки оставлен Hibernate ddl-auto=update. Перед подключением
старой PostgreSQL-базы сделайте резервную копию: переход double → numeric(19,2)
может округлить старые цены, а некорректные/пустые значения нужно исправить заранее.
Миграция произвольной существующей базы автоматически не гарантируется.
Для промышленной эксплуатации нужны версионируемые миграции и эксплуатационные настройки.

`./mvnw clean verify` запускает интеграционные тесты с отдельной H2-базой.
GitHub Actions запускает тот же набор на PostgreSQL 16 через TEST_DB_URL,
TEST_DB_USERNAME, TEST_DB_PASSWORD. Тестовый профиль использует create-drop:
не указывайте в TEST_DB_URL базу с нужными данными.

## Как изучать код

Комментарии к классам и методам написаны по-русски в формате Javadoc (`/** ... */`).
В IntelliJ IDEA их можно читать прямо в файлах или в подсказке документации символа.

Рекомендуемый порядок:
1. `ProductCloudJpaApplication` — запуск Spring Boot и создание компонентов.
2. `Product` — сущность, идентификатор, BigDecimal и правила корректных данных.
3. `ProductRepository` — стандартные операции Spring Data JPA.
4. `ProductService` — транзакции, пагинация и изменение управляемой сущности.
5. `ProductView` и `ProductForm` — разделение данных для вывода и ввода.
6. `ProductsController` — маршруты, Model, валидация и перенаправление после POST.
7. `templates/products.html` — построение страницы средствами Thymeleaf.
8. `ProductCloudJpaApplicationTests` — примеры ожидаемого поведения и пограничных случаев.
9. `pom.xml`, `application*.properties`, `.github/workflows/build.yml` — сборка, профили и CI.

При открытии каталога: браузер → GET /products → контроллер → сервис → репозиторий → БД.
Обратно идут сущности, затем DTO внутри Page, затем Model и готовая HTML-страница.
При добавлении: POST → ProductForm → валидация → сервис → Product → сохранение → redirect → GET.
При ошибке формы сохранения нет: контроллер повторно показывает страницу с ошибками.
Введите название и цену: продукт сразу добавится в вашу корзину и сохранится
в личном списке. Из списка можно повторно добавить продукт, удалить позицию
или очистить весь список. Старые записи общего каталога не отображаются.


## Личный кабинет и покупки

1. Откройте `/register`, введите имя, email и пароль (8–128 символов).
   При желании сразу выберите фото JPEG/PNG до 2 МБ.
2. Войдите на `/login`. На `/account` можно изменить имя, телефон и адрес,
   загрузить/заменить/удалить аватар и сменить пароль. Email служит постоянным логином.
3. Введите название и цену на `/products` или прямо в `/cart`: продукт сразу
   попадёт в корзину. В `/cart` доступны изменение
   количества (1–99), удаление позиции, полная очистка и точный расчёт суммы.
4. Заполните контакты и оформите заказ. Состав, цены и контакты сохраняются
   в `/orders`; отдельный заказ можно просмотреть и повторить по текущим ценам.

Оплата и исполнение доставки не подключены: оформление создаёт запись заказа,
не списывает деньги и не отправляет продукты. Об этом сказано перед оформлением.
История начинается с заказов, оформленных после добавления этой функции;
ранее добавленные в общий каталог продукты не считаются покупками.
Email не подтверждается письмом; отправка чеков и восстановление пароля через
почту пока не подключены. Профиль, корзина и заказы сохраняются в БД, включая
файловую H2 в профиле `demo`; не удаляйте папку `data/`.

### Устройство новых функций

- `account/` — профиль, формы, фото и регистрация.
- `security/SecurityConfig` — Spring Security, сессия, PBKDF2 и CSRF.
- `cart/` — личная корзина и ограничения количества.
- `order/` — атомарное оформление, снимки цен, история и повтор заказа.
- `templates/fragments/shop.html` — общая шапка с фото и счётчиком корзины.
- `static/account.css` и `account.js` — адаптивный кабинет и локальный предпросмотр фото.
- `CustomerShoppingTests` — вход, CSRF, изоляция пользователей, корзина,
  оформление без дубликатов, сохранность цен и безопасная обработка фото.

Hibernate добавляет таблицы `customer_accounts`, `cart_items`, `customer_orders`
и `customer_order_lines`. Существующая таблица `products` сохраняется.
Все изменения выполняются POST-запросами с CSRF-токеном. Владелец берётся
из авторизованной сессии, а не из параметров формы. Пароли хешируются PBKDF2;
фотографии проверяются по содержимому, обрезаются в квадрат и перекодируются
в JPEG без исходных метаданных. Исходное имя файла не используется как путь.
Смена пароля завершает текущую сессию. При публикации через HTTPS установите
`SESSION_COOKIE_SECURE=true`. Вход и регистрация пока не имеют лимита попыток.


## Личный список продуктов

Предварительно заполненного каталога нет. `/products` показывает только продукты,
введённые текущим пользователем. Доступны два независимых действия:

- «Удалить»/«Очистить корзину» убирают выбранные покупки из корзины, сохраняя список.
- «Удалить из списка»/«Очистить мой список» удаляют личные сохранённые продукты
  и соответствующие позиции корзины. Очистка охватывает все страницы списка.

После оформления история содержит неизменяемые снимки названий и цен, поэтому
удаление списка не меняет прежние заказы. Если продукт удалён из списка, повтор
заказа с ним предлагает сформировать новый список, не создавая частичную корзину.

В таблицу `products` добавляется nullable-колонка `owner_id`. Старые общие записи
не присваиваются случайному пользователю и не показываются в личных списках;
они остаются в БД для совместимости с прежними корзинами. Существующий продукт
в старой корзине можно удалить обычной кнопкой «Удалить» или очисткой корзины.
Новые продукты приватны: другой пользователь не может добавить или удалить их,
подставив чужой id. Образцы продуктов автоматически не создаются.

## Проверка и пояснения к коду

[Обзор качества и изменений](docs/code-review.md) описывает проверенные части,
исправления и ограничения учебного приложения. Javadoc на русском добавлен
ко всем явно объявленным классам, интерфейсам, записям, конструкторам, методам
и полям Java, в том числе в тестах и самостоятельном примере. Рядом с аннотациями
объясняется их назначение; компоненты record и локальные объекты основного кода
также снабжены пояснениями. Эти комментарии намеренно подробные для обучения.

`examples/bookshop` — отдельный пример JDBC/MVC со своим `pom.xml`, сервером
и базой. Он не входит в основной JAR Product Cloud и не запускается вместе с ним.
Его исходный уровень Java 17 сохранён; CI проверяет пример также на JDK 25.
Сборка примера: `./mvnw -f examples/bookshop/pom.xml clean verify`.

Основной проект использует Java 25 без preview. Классы JPA остаются обычными
классами, а DTO — записями record: у них разные задачи. Стандартный статический
`main` сохранён как привычная точка входа Spring Boot; компактный исходный файл
или нестатический main здесь не делают архитектуру лучше.
