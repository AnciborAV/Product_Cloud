# Зелёная лавка

Магазин на Java 25 и Spring Boot 4.1.2: каталог, личный кабинет, выбранные товары и публичные отзывы. Серверные страницы на Spring MVC и Thymeleaf, PostgreSQL, Spring Data JPA, Spring Security и миграции Flyway.

## Возможности

- Регистрация, вход по логину и паролю, выход. Логины нечувствительны к регистру, пароль хранится как BCrypt-хеш.
- Личный кабинет с фотографией, выбранными товарами и собственными отзывами.
- Загрузка JPEG/PNG до 2 МБ: проверка содержимого и разрешения, обрезка и перекодирование в JPEG 400×400. В PostgreSQL хранится только итоговый аватар, оригинал не сохраняется.
- Добавление и удаление выбранных товаров. Повторное добавление не создаёт дубликат, включая параллельные запросы.
- Отзывы с оценкой 1–5, редактированием и удалением. Один отзыв пользователя на товар; обновление заменяет прежний текст. Отзывы сразу публикуются во вкладке «Отзывы покупателей» с именем автора.
- Каталог с поиском по русским названиям, категориями и страницами по 12 товаров. Публичные отзывы также имеют постраничный вывод.
- Добавление товаров на витрину доступно только роли `ADMIN`. Регистрация всегда создаёт покупателя `USER`.
- Адаптивные страницы, доступные подписи форм, состояния пустых списков, уведомления и страницы ошибок.

## Запуск

Нужны JDK 25 и PostgreSQL 17 (либо Docker Compose). Maven запускается через Wrapper.

1. Скопируйте `.env.example` в `.env`, задайте собственный `DB_PASSWORD`.
2. Запустите PostgreSQL:

```sh
docker compose up -d postgres
```

3. Передайте переменные в процесс приложения. Compose читает `.env` сам, Spring Boot — нет. Для файла с указанным в примере форматом:

```sh
set -a
source .env
set +a
./mvnw spring-boot:run
```

Откройте http://localhost:8080. Создайте аккаунт по ссылке «Личный кабинет» → «Создать аккаунт».
Flyway автоматически создаст таблицы и начальный ассортимент. Повторный запуск не сбрасывает данные; Compose сохраняет их в именованном томе. Пароли аккаунтов и учётные данные базы не включены в репозиторий.

При использовании существующей PostgreSQL укажите `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`. Создайте отдельную базу для приложения и предоставьте пользователю права на её схему. Приложение проверяет соответствие JPA схеме (`ddl-auto=validate`); схему изменяет только Flyway.

## Администратор

Зарегистрируйте отдельный аккаунт, затем через доверенное подключение к базе назначьте ему роль:

```sql
UPDATE user_accounts SET role = 'ADMIN', version = version + 1,
 updated_at = CURRENT_TIMESTAMP WHERE username = 'your_admin_login';
```

После назначения роли войдите заново: форма добавления товаров появится внизу каталога. Общего административного пароля и публичного API назначения ролей нет.

## Проверка

```sh
./mvnw clean verify
```

Обычный запуск тестов использует H2 в режиме PostgreSQL, применяя те же миграции Flyway. Для проверки на настоящей PostgreSQL создайте **отдельную пустую тестовую базу**, передайте её настройки:

```sh
./mvnw test \
  -Dspring.datasource.url=jdbc:postgresql://localhost:5432/fresh_market_test \
  -Dspring.datasource.username=fresh_market \
  -Dspring.datasource.password="$DB_PASSWORD"
```

Тесты создают записи в указанной базе: не используйте рабочую базу магазина. Проверяются миграции, поиск и точность цены, рендеринг страниц, валидация, регистрация и вход, права администратора, CSRF, изоляция пользователей, конкурентное сохранение товаров, публикация и экранирование отзывов, редактирование и загрузка настоящего изображения.

## Архитектура

- `model/BaseEntity`: UUID, время создания/изменения, optimistic locking через `@Version`.
- `ProductEntity`, `UserAccount`, `SelectedProduct`, `Review`: сущности PostgreSQL; `Product` — неизменяемая модель представления товара.
- `repository`: JPA-запросы, загрузка связей через EntityGraph, блокировка строки пользователя для последовательного изменения его подборки и отзывов.
- `service`: транзакции и бизнес-правила; `AvatarProcessor` отдельно проверяет и преобразует изображения.
- `dto`: формы с Jakarta Validation; `controller`: маршруты, ошибки форм и Post/Redirect/Get.
- `db/migration`: версия схемы, внешние ключи, уникальность пар пользователя/товар, ограничения оценок и индексы.

Open Session in View отключён. Доступ к изменяемым данным определяется текущим пользователем из сессии, а не переданным в форме идентификатором владельца. Формы защищены CSRF; HTML от пользователей экранируется Thymeleaf. У сессии тайм-аут 30 минут, cookie HttpOnly/SameSite=Lax, страницы получают Content Security Policy и стандартные защитные заголовки Spring Security.

## Развёртывание

Сборка: `./mvnw clean package`, запуск: `java -jar target/Spring_DEMO-0.0.1-SNAPSHOT.jar` с переменными базы в окружении. При HTTPS задайте `SESSION_COOKIE_SECURE=true`. TLS, ограничение частоты входа/регистрации на reverse proxy, резервное копирование PostgreSQL и мониторинг необходимо настроить в среде размещения. Оформление заказов, оплата и восстановление пароля по почте в текущий объём функций не входят.
